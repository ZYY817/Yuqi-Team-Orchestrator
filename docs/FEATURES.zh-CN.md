# 🗺️ 功能实践情况

> 版本：`0.0.1`（Developer Preview）
> 本文说明产品要解决的问题、当前已实现的功能，以及后续计划更新的方向。

---

## 🎯 一、产品要做什么

Yuqi Team Orchestrator 解决的不是"怎么多开几个 Agent"，而是多代理协作里真正没人处理的问题：

- 🔍 任务分出去后，为什么中断、跑偏、无结果却没人知道
- ✅ 主控如何知道子 Agent 的结果是否满足验收条件
- 🧩 复杂任务怎样拆分、传递上下文和依赖
- 💰 哪些任务该用强模型，哪些可用低成本模型
- 📦 交付前如何检查代码、文档、测试是否真正完成
- 🛡️ 失败后如何有限重试、升级人工，而不是无限循环烧钱

**设计选择**：一个主控 + 多个直属子代理的持久任务图。用户只在主控对话说明目标；拆分、依赖、调度、日常异常、review 和最终汇总由主控统一处理。可靠性优先于表面并发——所有状态变化落入版本化事件流，未知结果 fail-closed，不允许用猜测替代事实。

## ✅ 二、现有功能（0.0.1 已实现）

### 📋 任务编排与调度

- 单个 Team 最多 **100** 个任务；并发保护上限 **1–100**，默认 **100**
- 任务依赖图调度：只派发已就绪任务；依赖、权限兼容性、`fileScope` 冲突都会影响实际并发
- `fileScope` 计划契约：声明计划变更区域，用于冲突预测、文件租约、恢复边界和 UI 展示
- 任务在实际派发时才创建子会话，等待中的计划任务不提前占资源

### 🧠 模型路由

- 三种策略：跟随主控、固定精确路由、实验性自动路由（`quick`/`standard`/`critical` 有序候选）
- Provider 范围默认 `controller-only`；跨 Provider 需用户明确配置 allowlist
- 调用失败后候选耗尽会明确报错停止，不盲目回到失败模型

### 🔎 验收与 Review

- Review 策略：`off` / `manual` / `quality-gate`，默认 `manual`
- `quality-gate` 下每个完成候选需通过独立审查；自动返工默认 2 轮、最多 3 轮
- 结构化证据裁判：支持 build / test / interface / screenshot 检查，结果为 `passed` / `failed` / `inconclusive`；子代理文字自报不能替代证据

### 🔐 权限、工作区与恢复

- 权限模式：Read Only / Workspace Write / Full access；默认 Direct 当前项目，Git worktree 隔离可选
- 暂停、继续、取消、任务重试、换模和重启对账，旧 attempt 与证据全部保留
- Controller-less recovery 只做 fail-closed 收口或暂停；runner 继续前必须恢复精确 controller 身份

### 🖥️ 用户界面

- Team 面板：任务状态、依赖、模型、权限、Token、耗时、证据、实际变更文件、会话导航、可逆归档
- 可选启动前任务图确认；团队设置支持中英文、并发、模型策略、Review 策略和默认权限
- Attention/待办入口集中呈现需要用户或主控处理的事项

### 📚 轻量项目知识

- `.yuqi-team/index.json` 项目索引：记录总体进度、架构决策、坑点和约定，支持稳定 ID 更新与链接引用；Markdown 为展示视图

## 🔮 三、后续计划更新

以下方向在规划中，属于演进意图而非版本承诺：

- 📚 **项目记忆总体规划**：把当前的轻量 JSON 索引扩展为更完整的项目记忆体系，让跨 Team、跨会话的长期上下文可积累、可检索
- 💰 **节省 token**：减少重复上下文传递和不必要的全量回放，优化调度与汇报链路的 token 消耗
- 🧠 **减少模型思考开销**：对简单调度、状态查询等路径降低推理负担，把强模型能力留给真正需要判断的环节
- ⚡ **提高定位代码速度**：改进证据、变更文件和会话之间的导航效率，让用户和主控更快定位问题代码
- 📦 **验收能力增强**：在现有证据裁判基础上扩展更确定性的交付检查能力
- 🔌 **Harness 生态协同**：子代理→主控消息通道等依赖 Host 能力的方向，随 Harness 演进接入

## 🚫 四、明确不属于当前版本

- 💵 预算硬门禁、货币成本结算、模型价格/质量评分
- 👥 多人协作、云同步、跨机器调度
- 🚀 自动 Git 合并、push、部署或生产发布
- 🌐 对所有 Provider、凭据、网络和 Host 组合的完整 E2E 保证
